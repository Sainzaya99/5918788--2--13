# 과제 13: 병합 정렬과 퀵 정렬 성능 비교
## 1. 실험 방법
무작위 정수 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000개를 생성했습니다. 동일한 데이터를 복사하여 Merge Sort와 Quick Sort(First, Random, Median3)로 오름차순 정렬했습니다.
- 비교 횟수: 데이터 값 비교만 계산하고, 피벗 선택 비교도 포함했습니다.
- 실행시간: QueryPerformanceCounter()로 정렬 시간만 ms 단위로 측정했습니다. clock()보다 짧은 시간을 정밀하게 측정하기 위해 사용했습니다.
- 메모리: 원본 배열을 제외한 추가 메모리를 근사 계산했습니다. Merge Sort는 n × sizeof(int) + 최대 재귀 깊이 × 40Byte, Quick Sort는 최대 재귀 깊이 × 48Byte로 계산했습니다(64비트 기준 가정). 실제 프로파일러 측정값은 아닙니다.
## 2. 실험 결과 (n = 20,000)

| 알고리즘	| 비교 횟수	| 시간(ms)	| 메모리(Byte) |
|---:|---:|---:|---:|
| Merge Sort | 260,913	| 2.2110	| 80,640 |
| Quick (First)	| 323,056	| 2.3033	| 1,488 |
| Quick (Random)	| 339,287	| 2.5875	| 1,632 |
| Quick (Median3)	| 320,841	| 2.4113	| 1,152 |


전체 데이터 크기의 측정값은 프로그램 실행 결과에 출력됩니다.
## 3. 결과 분석
데이터 크기가 커질수록 비교 횟수와 실행시간은 대체로 증가했습니다. Merge Sort는 모든 크기에서 비교 횟수가 가장 적었습니다. 데이터를 반으로 나누어 병합하기 때문입니다.

실행시간은 크기별로 차이가 있었습니다. 16,000개에서는 Quick (Median3)가, 20,000개에서는 Merge Sort가 가장 빨랐습니다. 실행시간은 시스템 상태에 따라 달라질 수 있습니다.

Merge Sort는 임시 배열을 사용하므로 메모리가 많이 필요했습니다. Quick Sort는 주로 재귀 스택을 사용하여 추가 메모리가 적었습니다. Quick Sort 중 Median3는 모든 크기에서 비교 횟수가 가장 적었으며, 피벗을 비교적 균형 있게 선택하기 때문입니다.

복잡도: Merge Sort는 시간 O(n log n), 공간 O(n)입니다. Quick Sort는 평균 시간 O(n log n), 최악 O(n²)이며, 재귀 스택 공간은 평균 O(log n), 최악 O(n)입니다.
